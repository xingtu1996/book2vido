# 01 · 分析：提示词为什么必须搬出代码

## 一、现状（实测，非推断）

提示词**内联**在 `src/book2vido/scriptwriter.py` 的 `OllamaProvider.script()` 里，是一串 Python 字符串拼接：

```
"你是一个把书/长文压成口播短视频脚本的助手。\n"
"请从下面【正文】提炼最多 " + str(max_n) + " 句口语化……"
…
```

全仓核查（含 `tools/`、`icons.py` 的注入项）：

| 提示词相关物 | 位置 | 性质 |
|---|---|---|
| 主提示词文本 | `scriptwriter.py`（约 16 行拼接） | **内联在代码里** |
| 注入的受控清单 `concept` | `icons.py` 的 `CONCEPTS`（85 词） | 同为注入项，但 SSoT 属图标层 |
| `think` 开关 | `config.yaml` + `providers.build()` | 已在配置层，**不在**提示词里 |

**关键事实**：提示词是本链路**唯一的「模型行为」来源**（宪法铁律六：7 环节只有分镜用模型），
但它住在一个 `.py` 文件里 —— 改它等于改代码，且**没地方写"这条约束是为什么"**。

## 二、四个问题（按严重度排序）

### P0 · 改了提示词，缓存不会失效 → 「改了像没改」

`cache.script_key` 的因子：

```
book_hash | model | think | max_sentences | sha256(章节文本)
```

**没有提示词**。而提示词是影响分镜内容**最直接**的因子。后果：

- 用户把提示词改了 → 键不变 → `hit_script` 命中**旧分镜** → 产出与改动前完全一样
- 退出码 0、日志显示"缓存命中"、**毫无异常** —— 典型的"静默走错分支"
- 用户会先怀疑自己改错了文件，再怀疑模型没生效，最后才可能想到缓存

这与宪法铁律六自设的验收判据**直接冲突**：

> 「新增任何缓存时必须同时回答『人改它生效吗』」

提示词就是"人改它"，而当时答案是「不生效」。**本 spec 首先是一条欠账的偿还，不是新功能。**

### P1 · 提示词没有注释的容身之处

每条约束背后都有实证理由（`≤20 字` 来自卡片排版容量、`concept 必须从清单选` 来自"12 卡散进 16 图标撞车"），
但写在 Python 拼接里只能靠 `#` 注释**另起一段**——离被说明的那行很远，
且读者要在一堆字符串引号里找。**注释与约束分家，等于没有注释。**

### P2 · 产物无法回答「这版分镜是哪版提示词出的」

`script.json` 记了 `model` / `think` / `created`，但没记提示词版本。
换模型、调提示词后要对比产出时，只能靠文件时间戳和记忆。
B16 那次数字漂移（改 md 没重渲染 HTML）就是同类问题的前科。

### P3 · 分发包里没有提示词，用户改不了

`.app` 只拷 `src/book2vido/` + `config.yaml` + `assets/icons/`。
将来开源后，用户想按自己的素材调提示词，只能改源码再重新打包 —— 门槛高得离谱。

## 三、方案对比（5 个，4 个否决）

| # | 方案 | 优点 | 否决/采纳理由 |
|---|---|---|---|
| A | 留在代码里，只补注释 | 改动最小 | ❌ 仍要改 Python；**仍不进缓存键**（P0 没解决）；注释与约束分家（P1 没解决） |
| B | 放包内 `src/book2vido/prompts/` | Python 惯例 | ❌ `.app` 里源码在 `Resources/app/book2vido/`，`parents[2]` 回溯到 `Resources/app/`，**找不到**；且 pip 要额外配 `package-data` |
| C | **放项目根 `prompts/`（与 `config.yaml` 同级）** | ✅ 与 `config.yaml` 同一套定位法（`parents[2]` → 项目根 / `Resources/`），已验证；用户一眼能看到；打包一行 `cp -R` | ✅ **采纳** |
| D | 写进 `config.yaml` | 一个文件搞定 | ❌ YAML 里放 700 字中文长文本 = 缩进/转义地狱，`|` 块还得自己管换行；注释也不能就近 |
| E | 上 Jinja2 模板引擎 | 占位符最灵活 | ❌ 只有 3 个占位符。为它引入依赖违铁律三的最小依赖精神（**且模板引擎的表达力会诱惑人把逻辑写进提示词**） |

### 版本号 vs 内容哈希（本 spec 最关键的一个决策）

| 做法 | 结果 |
|---|---|
| 用 `version: 1` 当缓存失效开关 | ❌ **靠人记得升版本号，迟早会忘**。忘了 → 又回到 P0（改了像没改），只是这次连"改文件"这个动作都被自己抹掉了 |
| 用渲染后内容的 `sha256` | ✅ **自动**：改正文一个字就变；改注释不变（注释已被剥掉） |
| 两者都用 | ✅ **采纳**：哈希负责正确性（缓存失效），版本号 + `body_hash` 负责可读追溯（写进 `script.json` 给人看） |

## 四、为什么指纹要分两层

| 名字 | 算的是什么 | 用在哪 | 为什么不合并 |
|---|---|---|---|
| `prompt_fingerprint` | 模板 + 注入项（`concept_list`），**不含章节文本** | 缓存键 | `pipeline` 必须**先算键、再决定要不要调模型**；而章节文本在那一步还没有 |
| `body_hash` | 模板正文（稳定，不随章节变） | `script.json` 的 `prompt_hash` | 人读追溯要的是"哪版提示词"，每章都不同的哈希没法比较 |
| 渲染后全文 | 含章节文本 | — | 只用于校验（golden 比对），**不进键**：章节文本已在键里，重复无益 |

## 五、剥注释：为什么需要两条规则

注释要"就近"，就必须允许它夹在正文行之间；但**注释一旦漏剥，就会被当提示词送进模型** ——
白烧 token，且可能改变模型行为（模型会试图理解那段 HTML）。规则：

1. 注块**独占一行** → 整行连同换行一起删（保证不留下空行，从而不改变正文的换行结构）
2. 注块**在行内** → 只删块本身（保留该行其余内容）

第 1 条是"逐字节一致"能成立的关键：正文的换行结构必须与搬出前完全相同。

## 六、影响面

| 受影响 | 怎么受影响 | 是否可接受 |
|---|---|---|
| **既有缓存全部失效一次** | 键里多了 `|prompt_fp` 段 → 所有历史 `script_key` 失配 | ✅ 必须如此：历史缓存产出的分镜**来源不可信**（说不清用的哪版提示词），重跑一次是正确的 |
| `pipeline.run()`（T2V-001 兼容入口） | 它走 `Cache(enabled=False)`，键不参与 | ✅ 行为不变 |
| `RuleFallbackProvider` | 不读提示词，`prompt=None` / 指纹 `""` | ✅ 降级路径不受影响；改提示词也不会让它的结果"看起来变了" |
| 外部脚本（`tools/probe_*.py`） | `script_key` 新增**可选**参数（默认 `""`） | ✅ 不传照旧跑 |
| 老 `script.json` | 新增两个字段，`from_json` 用 `.get()` 读 | ✅ 向后兼容（已测） |
| 打包体积 | `prompts/` 约 10 KB | ✅ 可忽略 |

## 七、实现期发现（Reverse Sync）

> 铁律 3：发现缺陷 → 先补文档（根因/漏 AC/回归用例）→ 再改代码。

### F-A · 正文标记被注释里的字面量"截胡"（已修）

- **现象**：`verify_prompt.py` 第一跑，渲染结果只有 **5 个字符**：`` ` 与 ` ``。
- **真因**：`parse()` 用**子串匹配**找标记（`rest.split(BEGIN, 1)`），而文件头说明里写了
  「`` `<!-- @prompt:begin -->` 与 `<!-- @prompt:end -->` 之间… ``」——
  第一个命中的是**注释里提到的那个字面量**，于是"正文"变成了两个反引号之间的内容。
- **修法**：标记一律按**整行精确匹配**（`^[ \t]*<!--[ \t]*@prompt:begin[ \t]*-->[ \t]*$`）。
  这样正文、注释里随便提到标记都不再歧义 —— **修的不是这一处，是这一类**。
- **为什么值得记**：这是"匹配到不该匹配的东西 → 不报错、只静默取错内容"的又一例，
  与错题库既有家族同源。**而它是被"逐字节 golden 校验"当场抓住的，不是靠人眼**——
  说明"先固化基线、再动代码"的顺序值那 2 分钟。

### F-B · 改回原样仍 miss（已知行为，非缺陷）

`.keys.json` 只记**最后一次**键值：改了提示词（写入新键）再改回来，旧键已被覆盖 → 仍会重跑一次模型。
不是 bug（缓存只能回答"上次是什么"），但**必须写进文档**，否则用户会以为缓存坏了。
→ 已写进 `prompts/scriptwriter.md` 与 `doc/15`。

### F-C · `CONCEPT_KEYS` 是一条"注释声称 ≠ 实际"（已修注释）

`icons.py` 里 `CONCEPT_KEYS` 的注释写着「供 prompt 注入与 resolve 优先匹配使用」，
但全仓核查**没有任何调用点**：prompt 注入走的是 `CONCEPTS` 的**插入顺序**，
本地匹配走的是另一个 `_SORTED`。→ 保留变量（长词优先注入是个合理备选项），**把注释改成真话**，
并注明"将来要怎么改"。→ 登记错题库 L-15。

### F-D · 验证脚本自己漏了一步（探针失效）

AC-11（缺 `prompts/` 时构建自检必须 `die`）第一次执行时，我忘了真的移走目录，
于是 `--check` 正常通过、退出码 0 ——**差一点把"探针没生效"当成"通过"**。
补跑后退出码 1、错误信息正确。
→ 与 `hidden-contract-audit` 里那条"探针给出失败时先证明探针是对的"同源，这次是反向：**探针给出成功时，也要确认它真的测到了**。
