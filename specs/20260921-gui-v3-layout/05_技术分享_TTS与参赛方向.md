## 一、TTS 技术栈（你之前问的"本地 vs 云"）

TTS = Text To Speech，文字转语音。Book2Vido 里有两条路：

### 1. 本地 TTS（macOS say 命令）

**是什么**：macOS 系统自带的 `say` 命令，零安装、零成本、完全离线。

**音色**（你之前试听的）：
| 音色 | 性别 | 效果 | 推荐度 |
|---|---|---|---|
| Sandy | 女 | 最自然，Siri 同款 | ⭐⭐⭐⭐⭐ |
| Shelley | 女 | Siri 同款，稍机械 | ⭐⭐⭐⭐ |
| Flo | 女 | 偏年轻 | ⭐⭐⭐ |
| Tingting | 女 | 老版，最机械 | ⭐⭐ |

**优点**：
- 零成本、零安装、零网络
- 隐私完全本地
- 响应快（即时）

**缺点**：
- 音色少，中文不够自然
- 没有情绪、停顿控制
- 机器感重，像导航

### 2. 云端 TTS（edge-tts / 微软大声朗读）

**是什么**：调用微软 Edge 浏览器的免费 TTS 接口，本质是微软 Azure TTS 的"免费通道"。

**音色**（你选的晓伊 Xiaoyi）：
- `zh-CN-XiaoyiNeural`：女声，活泼，最自然
- `zh-CN-XiaoxiaoNeural`：女声，温柔
- 一共几十种中文音色

**优点**：
- 自然度接近真人，有情绪
- 支持语速、音调、停顿控制
- 音色多

**缺点**：
- 需要联网（这是你最纠结的点）
- 不是官方 API，随时可能被封
- 延迟比本地高 1-2 秒

### 3. 你现在的选择

**Book2Vido 当前策略**：
- 主用：edge-tts（晓伊）—— 效果好，同事听得舒服
- 降级：macOS say（Sandy）—— 断网时兜底

**为什么这样选**：同事用的时候需要联网（他要下载模型、传 PDF），联网状态下 edge-tts 效果好太多。真断网了 say 也能用。

## 二、这个产品的技术亮点（可以对外讲的）

### 亮点 1：全本地，零 API 成本

```
传统做法：PDF → 传云端 → OpenAI 总结 → 云端 TTS → 下载视频
Book2Vido：PDF → 本地 qwen3:8b 总结 → 本地/edge TTS → 本地 FFmpeg 合成
```

**成本**：¥0（只有电费）
**隐私**：文件不出本机
**对比**：一个 300 页的书，云端 API 总结一次可能要 ¥5-10，本地跑只要电费。

### 亮点 2：模型选型思路

不是"越大越好"，而是：
- 总结文案：qwen3:8b（8GB 显存就能跑）
- TTS：edge-tts 免费 + say 降级
- 视频合成：FFmpeg 命令行，零依赖

这套组合在 M1 Pro 16GB 上跑通了，普通 MacBook 就能用。

### 亮点 3：工程化思路

- 模块化：extractor → scriptwriter → visualizer → narrator → compositor
- 缓存机制：第二次跑同一本书，0.5 秒出结果（分镜缓存命中）
- 降级策略：TTS 断网自动切 say，模型没下载自动提示

## 三、参赛 / 对外讲的方向

### 方向 A：AI 应用创新类比赛

**一句话定位**：
> "把一本 300 页的书，1 分钟变成竖屏短视频——全本地、零成本、隐私安全。"

**讲故事的钩子**：
1. **痛点**：现代人没时间读书，但通勤有 30 分钟
2. **方案**：本地大模型把厚书浓缩成 30 秒短视频，通勤路上看完
3. **差异**：不联网、不传文件、不花钱——和市面上"AI 读书"产品完全不同
4. **技术**：本地 qwen3:8b + edge-tts + FFmpeg，一套在普通 MacBook 上跑通的流水线
