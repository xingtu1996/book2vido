# 01 · Analysis（根因与背景）

## 需求来源
身边人：「字太多看不下去」——本质是**消费端门槛**：内容形态太重，用户不愿读。他要的是「轻的形态」（听 + 扫），不是「便宜的制作」。

## 痛点（赛道现状）
- 现有开源全走「全自动文生视频」：huobao-drama(15k★) / ViMax(12k★) 全烧 Kling/Seedance/Veo，单条 ¥5–30+。
- 朋友吐槽「成本太高」正是这个坑。

## 机会（空白）
- 低成本半自动路线几乎无人占：Book2Video 仅 6★，且仍烧图像 API。
- 行途手里有零件：Ollama 本地 LLM + pypdf + AntV/Excalidraw/unDraw + edge-tts + FFmpeg + UI-TARS。

## 决策
**集百家之长**：拼一条零公司资源、≈¥0 的流水线，MVP 优先跑通，开源引流。

## 风险
- R1: 本机 16GB，本地 8B 档（qwen3:8b）占半内存，质量弱 → boss 已授权「视觉可以少一些」，容忍。
- R2: edge-tts 需网 → 断网回退 macOS say（本地）。
- R3: 朋友端不可能装 Ollama → 当前 MVP 定位「行途自己出片」，自助工具（小程序壳）为后期。
