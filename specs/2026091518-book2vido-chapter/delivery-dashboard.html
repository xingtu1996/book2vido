本轮抓到的 5 个缺陷

严重手改分镜被静默丢弃
现象
改了 script.json 里的一句话，重跑却还是老视频，而且不报错。
真因
video_key 挂的是 script_key（由输入文本推导）。手改输出文件不改输入 → 命中旧分镜渲染的成片。
修法
改挂 sha256(分镜规范化 JSON) 指纹 → 改一句只重渲染下游，LLM 不跑。
实测
日志出现「分镜：缓存命中…跳过模型」+「画面：渲染」→ 只重跑下游，8.5~13s
中「全命中」却要等 19.9 秒
现象
缓存全命中，理论上应该秒回，实际墙钟 19.9s。
真因
命中路径仍解析全书：extract_pages 5.9s + outline.build 6.0s = 11.9s 白干。只算了「要不要重做」，没算「命中时顺手做了多少无用功」。
修法
大纲优先读 outline.json + 章切片落 text.txt + lazy_pages() 把抽页推迟到真正需要时。
实测
19.9s → 0.502s（40×）
中文档里承诺的「人工可改口子」是假的
现象
代码注释与设计文档都写「outline.json 落盘 = 人工可改的口子」，实际手改完全不生效。
真因
每次跑都 build() 重建，save() 落的文件白存。与上一个缺陷是同一类。
修法
改为优先 load()；手改即生效。日志会打印「大纲：缓存命中…（读 outline.json，手改生效）」。
实测
render_tree(build) ≡ render_tree(load)：93 条 / 22 顶层 / 页码范围逐条相同，读缓存不引入漂移。
中长章切片的「章尾」被悄悄切掉
现象
长章均匀采样首/中/尾，但章节最后 12 个字始终不在切片里。
真因
三段各 833 字 = 2499，加 2 个省略分隔符（各 4 字）= 2507 > 2500 → 兜底 text[:2500] 从尾部切，恰好切掉尾段存在的意义。
修法
预算先扣分隔符 + 段间换行计入预算；并加 segmenter.VERSION（改算法必须 +1），否则旧切片被静默复用、改进等于没做。
实测
全 22 章逐章通过：长章 2498 字，首 / 正中 / 末 12 字全部命中。
严重--chapter 0 静默走整本出片
现象
--chapter 0 没有任何输出、没有报错、退出码 0——却跑了一条整本书的片子。
真因
bool(a.chapter or ...)：bool(0) is False → 被判成「没给章参数」→ 走 T2V-001 老路径。
修法
改用 is not None 显式区分「没给」与「给了 0」；顺带 --chapters '' 明确报错、输入文件不存在由 20 行 traceback 改为一句人话。
实测
0 / -1 / 999 → 退出码 1 + 明确越界信息；abc / '' → 退出码 2 + 明确提示。
模式识别（本轮最大收获）：5 个缺陷里 4 个同属一类——「键 / 缓存 / 落盘文件」这类 看不见的契约。它们不报错、只静默走错分支或静默不生效，happy path 全绿。 加上此前的项目级案例（术语改一处、信息图 HTML 改了 PNG 没重渲染），这类缺陷已构成模式， 故已沉淀为 skill hidden-contract-audit。
