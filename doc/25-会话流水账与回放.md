# 25 · 会话流水账与回放（Session Ledger & Replay）

> **定位**：回答一个问题——**「这个项目的每一段工作是怎么发生的，能不能回放？」**
> 它是四层记录的**总索引**：任何 AI harness（WorkBuddy / Claude Code / Codex / 换任何模型）接手时，
> 不靠某次会话的记忆，也能从磁盘重建全部来龙去脉。
>
> 建立：2026-09-16 ｜ 维护：每轮会话收尾登记一行（见 §4 纪律）

---

## 1 · 四层回放模型（每层回答一个问题）

| 层 | 载体 | 回答什么 | 粒度 |
|---|---|---|---|
| ① **产物层** | [`CHANGELOG.md`](../CHANGELOG.md) | **改了什么**（行为 / 接口 / 产物结构） | 每次有外部影响的变更 |
| ② **决策层** | [`specs/`](../specs/README.md) + 工作空间 `specs/20260915-book2vido产品化与商业化/` | **为什么改 / 为什么不做**（触发条件、待拍板台账） | 每个决策点 |
| ③ **错题层** | [`doc/lessons/`](lessons/README.md) | **踩过什么坑**（错题编号 L-xx，防复发） | 每个坑 |
| ④ **会话溯源层** | [`SESSION_PROVENANCE.json`](../SESSION_PROVENANCE.json) + 本文件 §3 登记表 | **哪次会话 / 什么模型 / 怎么重建** | 每轮会话 |

**回放路径**（新会话接手时按序读，约 5 分钟）：

```
SESSION_PROVENANCE.json（哪次会话、cwd 陷阱）
  → 本文件 §3 登记表（历轮会话 → 各自改了什么）
    → CHANGELOG 对应版本块（改动明细 + 验证证据）
      → specs 对应包（当时的决策与不做的理由）
        → doc/lessons（别再踩的坑）
```

## 2 · 为什么只有 CHANGELOG 不够

CHANGELOG 是**结果账**：它记「改了什么」，不记「哪次会话改的、当时还否决了哪些方案」。
被否决的方案只存在于会话里——**会话结束就丢了**，下一个 AI 会把同样的方案再提一遍，
再被同样地理由否决一遍（本项目真实发生过，见 `doc/17` 结构诊断的动机之一）。

所以本文件 §3 的登记表，**专门登记"被否决的方案 + 否决理由"**——这是 CHANGELOG 不收的部分。

## 4 · 维护纪律（每轮会话收尾）

1. **产物**进了 `CHANGELOG.md`（有外部影响的才算）；
2. **决策与否决**进了 `specs/`（否决方案写进本文件 §3 那一行）；
3. **坑**进了 `doc/lessons/`（带复现与防复发）；
4. **本文件 §3 加一行**（哪怕这轮只读没写——"查了什么、为什么没动"也是账）；
5. 跨工作空间的登记（`CHANGELOG.md` / `产出索引.md` / `DIRECTORY.md` 三重登记）按工作空间规则走，本表只管 **repo 内**的回放链。

> 缺任何一层＝回放链断：只有 CHANGELOG＝不知为什么；只有 specs＝不知改没改；只有会话＝换 harness 全丢。

## 5 · 会话原始记录（jsonl）怎么找

WorkBuddy / Claude Code 的会话原文按 cwd 哈希存于
`~/.workbuddy/projects/<cwd-哈希>/<sid>.jsonl`（只在消息**实际发出时**落盘）。
⚠️ 两个已知陷阱：
- **输入队列不落盘**：排队未发出的消息重启即丢，不会进 jsonl（2026-09-16 实证）——重要指令落 `inbox/待发.md`；
- **cwd 陷阱**：会话 cwd 可能是历史残留目录（如 `<残留目录·勿用>`），以 `SESSION_PROVENANCE.json` 的 `project.root` 为准，**不以 cwd 为准**。
