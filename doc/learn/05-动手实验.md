# 05 · 动手实验（做完这 6 个，你就不只是"听说过"了）

> 每个实验都配**能直接粘走跑**的命令和「你应该看到什么」。
> 建议按顺序做 —— 它们串起来正好是整条链路。

> **准备一份输入**：本书仓库**不收录受版权书籍**（`samples/books/` 已 gitignore）。
> 自备一本文本型 PDF 或一篇长 Markdown 放到 `samples/books/`，
> 下面统一写作 `samples/books/<你的书>.pdf`。
> 用 PDF 时先用 `list` 看目录序号（**序号含序言等，不等于书上的章号** —— 见 [`../10-目录索引与按需生成.md`](../10-目录索引与按需生成.md)）。

## 实验 1 · 不跑模型也能出片（感受"降级路径"）

**目的**：理解为什么"没有 AI"这个项目依然是完整的。

```bash
cd <仓库根>
PY=$HOME/.workbuddy/binaries/python/envs/default/bin/python
printf 'llm:\n  provider: rule\n' > /tmp/rule.yaml
PYTHONPATH=src $PY -m book2vido run --input samples/books/<你的书>.pdf \
    --chapter 1 --out /tmp/exp1.mp4 --config /tmp/rule.yaml
```

**你应该看到**：出片成功，耗时约 0 秒（没有模型环节），但口播句是**原文的前几句**，不是"压出来的"。

**想明白**：模型的价值是"压缩成能口播的话"，不是"必须有"。
这条降级路径让项目在用户没装 Ollama 时**不崩** —— 宁可出质量低的片，也不报错退出。

> ⚠️ 反过来这个坑也在这：写脚本忘了传 `--config`，`config.load()` 默认就是 `rule`，
> 于是"分镜 0.02 秒就出来了"。**看到快得离谱，先怀疑自己是不是在跑 rule。**

## 实验 2 · 看模型真正收到了什么

**目的**：理解"就近注释"和"占位符"到底怎么回事。

```bash
$PY tests/verify_prompt.py --show | head -40
```

**你应该看到**：干净的一段提示词 —— 文件头那几十行说明、正文里夹的注释**全都不在里面**，
`{{max_n}}` 已经变成 `12`、`{{concept_list}}` 已经变成 85 个概念词。

**想明白**：模型收到的和你看到的**不是一个东西**。
所以"我以为我改了提示词"和"模型真的收到了新的"之间，隔着一个加载器 ——
这就是为什么要有 `verify_prompt.py` 做逐字节 golden 比对。

## 实验 3 · 改一个字，看缓存失效

**目的**：亲眼看到"内容指纹"驱动缓存失效，而不是版本号。

```bash
# ① 先出一次片（这时候会跑模型，约 36s）
PYTHONPATH=src $PY -m book2vido run --input samples/books/<你的书>.pdf \
    --chapter 1 --out /tmp/exp3.mp4 --config config.yaml

# ② 再出一次 —— 应该命中缓存
PYTHONPATH=src $PY -m book2vido run --input samples/books/<你的书>.pdf \
    --chapter 1 --out /tmp/exp3.mp4 --config config.yaml
#   → 「分镜：缓存命中」· 耗时 0.0 s

# ③ 在 prompts/scriptwriter.md 的**正文区**改一个字（比如一个标点）
#    然后：
$PY tests/verify_prompt.py      # 会红：与 golden 不一致（这是对的！）

# ④ 再出片 —— 分镜缓存失效，重新跑模型
PYTHONPATH=src $PY -m book2vido run --input samples/books/<你的书>.pdf \
    --chapter 1 --out /tmp/exp3.mp4 --config config.yaml
#   → 「分镜：调用模型」· 耗时回到 36s 量级

# ⑤ 收尾：把改动还原，跑 $PY tests/verify_prompt.py --update
```

**你应该看到**：改正文一个字，缓存就失效；**改注释则不会**（注释被剥掉了，不计入指纹）。

**想明白**：`version: 1` 那个号只是给人读的标签，**失效靠的是 sha256**。
人记得升版本号 → 迟早忘一次 → 花两小时查"为什么改了没生效"。

## 实验 4 · 量一次你自己的机器

**目的**：把"本地推理慢不慢"从听说变成你自己的数字。

```bash
ollama pull qwen3:8b                       # 首次约 4.9 GB
$PY tools/bench_ollama.py --model qwen3:8b
```

**你应该看到**：冷启动 / 预填充 / 解码速率 / 首字延迟 / 思考开销五项，
结果同时写进 `/tmp/ollama_bench.json`。

**想明白**：解码速率是**硬上限**（每秒十几个字）。
这意味着"让模型多写"和"让模型少写"直接对应时间 —— 所以才有关思考的开关。

## 实验 5 · 手改中间产物，只重跑下游

**目的**：理解缓存分层为什么值钱。

```bash
# ① 找一份已经跑过的分镜缓存
find cache -name "script.json" | head -3

# ② 用编辑器打开，改掉其中一句的 text（比如加一个"啊"）
# ③ 重新出片
PYTHONPATH=src $PY -m book2vido run --input <对应输入> --chapter N \
    --out /tmp/exp5.mp4 --config config.yaml
```

**你应该看到**：分镜**没有**重跑（还是你手改的那一版），只有成片重出。

**想明白**：分层让你能在**最便宜的那一层**介入。
不满意一句话改 `script.json` 就行，不用重新跑 36 秒的模型。

## 实验 6 · 断网跑一遍（这条最硬）

**目的**：验证"内容不出本机"不是口号，是可执行判据。

```bash
$PY tests/verify_offline.py --tts say
```

**你应该看到**：脚本在 **socket 层拦截全部外网**，然后跑一次真实出片，
最后断言 **外网请求数 = 0** 且成片产出。

**想明白**：这条脚本守的是**本机永远测不出来的东西** —— 有网时一切正常，
用户断网才发现挂了。同理还有 `tests/verify_icons.py`（图标缺失在有网时会被静默下载补齐）。

> 这就是为什么 `tests/` 里的东西必须"守住本机测不出来的"：
> 手测能发现的问题，写脚本是负担；手测发现不了的，写脚本是资产。
