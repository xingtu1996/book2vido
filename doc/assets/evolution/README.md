# 产物演进档案 · assets/evolution

这里是 book2vido **画面产物各代代表帧**的留存处。目的不是展示「今天做得多好」，
而是留下「**它是怎么一步步变成这样的**」——包括中间读不了的、只有骨架的那几版。

看板：`../../14-产物演进史.html`（人看）｜本文件：目录规范（用/维护时看）

---

## 一份档案要能一直长下去

固定四段式，按画面「能不能读」分档，不按代码版本分：

| 档 | 判据 | 一句话 |
|---|---|---|
| **没内容** | 关键 1 段文字**没有渲染出来**，或文字被压到不可识别 | 版式在，肉不在 |
| **有内容** | 文字与图标都在，但**图标语义与文案不相关**（重复图形、中性图形凑数） | 能读，但读不懂 |
| **有信息** | 图标能表意、文案一句说清，同批卡片**无重复图形** | 能读也能懂 |

> ⚠️ 「有内容」和「有信息」**不能只看一个指标**。两版的画面填充度可以几乎一样
> （实测 0.0406 vs 0.0491），必须同时看**同批卡片用了几个不同图形**——
> 「有没有」与「对不对」是两件事。

## 文件命名

```
<序号>_<日期>-<时刻>_<定名>_<一句话实况>.png
```

- 序号两位，从 `01` 递增（= 时间顺序，也是上传顺序）
- 时刻用产物**生成时间**（`ls -l` 或 `ffprobe` 的 mtime），不写「大概上午」
- 定名要**人话**：条形码 / 白板 / 能读 / 能懂 —— 不要写「v1 版本」
- 追加新代际**只加序号，不改旧文件**（旧文件名一旦被引用，改名=断链）

## 怎么取一帧（不要手截屏）

```bash
FF=/opt/homebrew/bin/ffmpeg          # 沙箱内 ffmpeg 不在 PATH，用绝对路径
$FF -y -v error -ss <秒> -i <产物.mp4> -frames:v 1 -vf scale=440:-1 <输出.png>
```

`-ss` 建议取卡片**停留期**（不是切场瞬间），否则会抽到交叉淡入。

**怎么知道哪一帧信息量最高**：看「中部区域非白墨量」。
若某一帧该值接近 `0.000x`，而整体正常值在 `0.04–0.06`，那就是**坏帧或空白帧**。

```bash
# 快筛：抽样 20+ 个时间点，取墨量最高的一帧当封面
# ROI = 高 12%–80% / 宽 8%–92%；判据 = min(RGB) < 215 的像素占比
```

## 追加一条新代际的最小动作

1. 抽帧 → 按命名规范存进本目录
2. 到 `../../14-产物演进史.html` 的「§5 演进台账」加一行（含时刻 / 产物 / 实况 / 填充度 / 图标去重 / 原因）
3. 若属于新的「档」（比如从「有信息」再进到「好懂」），同步补 §0 的色带说明
4. 数字回挂口径，**不要抄旧的填充度**——重跑一次
