# 15 · 提示词与模型适配

> 本文回答一件事：**换模型 / 追 SOTA 时，提示词该怎么改、怎么验、怎么留痕。**
> 提示词资产本体在 [`../prompts/scriptwriter.md`](../prompts/scriptwriter.md) —— 逐条约束的"为什么"
> 写在约束**旁边**（就近注释），本文只讲方法论与操作。

## 一、为什么提示词是资产而不是代码

宪法铁律六定下「7 环节只有分镜用模型」。这意味着：**整条流水线的"智能"只有一个来源 —— 那段提示词。**

它住在 Python 文件里的三个代价（T2V-007 之前的状态）：

| 代价 | 具体表现 |
|---|---|
| 改它要动代码 | 非程序员改不了；改完要走代码评审、要清 `__pycache__` |
| 注释无处安放 | 每条约束背后的实证理由只能另起 `#` 段落，离被说明的行很远 |
| 没有追溯 | 产物说不清"这版分镜是哪版提示词出的" |

搬出来之后它还是**唯一**影响模型行为的输入，但变成了"人能改、改了会生效、改过有痕"的东西。

## 二、文件长什么样

```
prompts/scriptwriter.md
├── frontmatter            id / version / applies_to / updated / placeholders（人读）
├── 文件头说明区            怎么读 / 怎么改 / 现在什么模型（不进 prompt）
├── <!-- @prompt:begin --> ─┐
│   提示词正文               │  ★ 真正送给模型的部分
│   <!-- 就近注释 -->        │  注块会被整块剥掉，不占 token
│   {{占位符}}               │  max_n / concept_list / chunk
├── <!-- @prompt:end -->  ──┘
└── 人读区                  模型适配记录 / 改动影响面 / 验证 SOP（不进 prompt）
```

**三个区严格分开**：标记之外的任何文字都不会进模型。所以可以放心在文件里写长注释、写表格、写历史。

## 三、怎么改（换模型的标准动作）

```bash
# ⓪ 先确认当前与基准一致（否则你不知道"变化"来自哪）
python tests/verify_prompt.py

# ① 只换模型，提示词原样 —— 先看它在原提示词下的表现
#    改 config.yaml 的 llm.model，然后
PYTHONPATH=src python -m book2vido run --input <素材> --chapter 1 --out /tmp/base.mp4

# ② 再按新模型的脾气改提示词（一次只改一个变量）
#    改完立刻复核注释有没有剥干净、正文有没有被误改：
python tests/verify_prompt.py          # 会显示与 golden 的逐行 diff

# ③ 确认这次改动是"有意的"→ 更新基准
python tests/verify_prompt.py --update
git diff tests/prompt_golden.txt       # 人肉再看一眼

# ④ 抽一章真跑，对比产出
PYTHONPATH=src python -m book2vido run --input <素材> --chapter 1 --out /tmp/new.mp4

# ⑤ 在 prompts/scriptwriter.md 的「模型适配记录」里添一行
```

**为什么先只换模型、再改提示词**：一次改两个变量，产出变好变坏都分不清是谁的功过。

## 四、改完会自动发生什么（三条，都不需要你操心）

| 机制 | 效果 |
|---|---|
| **缓存自动失效** | 缓存键挂"渲染后提示词的指纹"。改正文一个字 → 键变 → 该章下次必重跑模型。**不需要记得升 `version` 号** |
| **产物留痕** | `script.json` 里记下 `prompt_version` + `prompt_hash` → 日后能回答"这版分镜哪来的" |
| **打包随行** | `prompts/` 会被拷进 `.app` 的 `Contents/Resources/`（与 `config.yaml` 同级）；漏拷则**构建直接失败**，不会发出坏包 |

## 五、改什么会影响什么

| 改动点 | 影响面 | 怎么察觉 |
|---|---|---|
| 角色句 | 整体文风（会从"口播改写"退化成"书面摘要"） | 抽一章看产出 |
| ≤20 字 | 卡片排版是否换行 | 看卡片，字挤就是超了 |
| `{{max_n}}` | 成片时长（改 `config.yaml` 的 `limits.max_sentences`） | 时长实测区间见 `demo/README` 的数字口径表 |
| `keyword` 规则 | 卡片大标题 | 抽一章看；**不要把 keyword 也做成受控清单**（会变"标签腔"） |
| `concept` 规则 / 词表 | 图标命中率 | 判据：**12 张卡应出现 12 个不同图形**（见 `doc/08-画面资产策略.md`） |
| few-shot 示例 | 全线上（模型会模仿示例的口气与粒度） | 必须对照重跑 |

## 六、两条容易踩的坑（实测）

### 坑 1 · 改错一个字再改回来，仍会重跑一次模型

`.keys.json` 只记**最后一次**键值。所以：
改 A（写新键）→ 改回 A（键回到旧值，但文件里已是新键）→ **仍 `miss`**。

**不是 bug**：缓存只能回答"上次是什么"。知道就好，别误以为缓存坏了。
（若确实要避免，可用 `--cache-dir` 指定一个新缓存目录做实验，别动正式缓存。）

### 坑 2 · 注释写法决定它是否"免费"

| 写法 | 剥注释后 | 结果 |
|---|---|---|
| 注块独占一行 | 整行连换行一起消失 | ✅ 不影响正文，不占 token |
| 注块夹在行内 | 只删注块本身 | ✅ 保留该行其余内容 |
| **注块未闭合**（少了 `-->`） | 后面的正文会被一起吞掉或残留 | ❌ `verify_prompt.py` 会报"残留 `<!--`" |
| 提到标记字面量 | — | ✅ 安全：标记按**整行**匹配（这是修过一次的坑，见错题库 L-16） |

## 七、试验性改动不要污染仓库文件

想试一版激进提示词？**复制一份到别处**，用 `config.yaml` 指过去：

```yaml
llm:
  prompt_file: /path/to/我的实验版.md   # null = 用仓库内的 prompts/scriptwriter.md
```

产物的 `prompt_hash` 会告诉你它到底用了哪一份（已实测：外部副本 `7eebba9fa500` ≠ 仓库版 `def6f167f61a`）。
试出结果再决定要不要并回仓库 —— **试验的痕迹留在 `/tmp`，不留在这份资产里**。

## 八、与代码的边界

| 东西 | 归谁 | 为什么 |
|---|---|---|
| 提示词正文、约束解释、示例 | `prompts/scriptwriter.md` | 模型行为的唯一来源，要能独立改 |
| `concept` 受控清单（85 词 → 图标名） | `src/book2vido/icons.py::CONCEPTS` | 它是"词→图标"映射，属于图标资产；提示词只放 `{{concept_list}}` 占位 |
| `think` 开关 | `config.yaml` | 它是模型调用参数，不是提示词内容 |
| 取料（跳版权页、按章切片、预算） | `segmenter` / 调用方 | 送进提示词之前的事；提示词只负责「文本 → 分镜」 |
| 解析模型输出（正则捞 JSON、字段过滤） | `scriptwriter.py` | 这是"关进笼子"的机制，属代码 |

**边界判据**：改它需要 Python 吗？需要 → 代码。不需要 → 资产。
