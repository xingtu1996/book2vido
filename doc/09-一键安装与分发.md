# 09 · 一键安装与分发（macOS .app）

> 目标：让**不懂命令行的人**双击一个图标就能用——拖 PDF 进去，出来一支短视频。
> 前提：全程本地、零 API 费用、零公司资源（见 CONSTITUTION）。

---

## 一、结论先行

| 问题 | 答案 |
|---|---|
| 能不能做成一键安装？ | **能**，`packaging/build_app.sh` 已产出可运行的 `dist/Book2Vido.app` |
| 安装包多大？ | **≈ 150 MB**（不含模型） |
| 为什么不把模型也塞进去？ | 模型 **4.9 GB**，塞进去安装包变 5.1 GB。所有同类工具（LM Studio / Ollama）都不内置模型 |
| 用户还需要装什么？ | **什么都不用**。Python 运行时、依赖、Ollama 二进制全部随包 |
| 唯一的例外 | **ffmpeg**：homebrew 版绑 18 个 dylib，不能独立分发 → 需换 static build（见 §五） |
| 怎么给用户？ | **`.dmg` 已可产出**：双击 → 拖进 Applications → 完成（见 §六·补）。体积 **53 MB** |
| 谁现在能用？ | **本机/同类环境**（系统已有 ffmpeg）。**发给别人会被 ffmpeg 卡住** —— 先补 §五 才能对外 |
| 首次运行的额外动作 | 自动下载模型 4.9 GB（**复用系统已有的 `~/.ollama/models`，不重复占空间**） |

## 二、体积账（实测，不是估算）

| 组件 | 大小 | 能否内置 | 说明 |
|---|---|---|---|
| Python 运行时（standalone 3.13） | **77 MB** | ✅ | 已实测「换个目录照样跑」，不依赖用户装 Python |
| 最小依赖 4 个（Pillow / pypdf / pyyaml / edge-tts + 链） | **≈ 25 MB** | ✅ | 代码里只 import 这 4 个（`torch`/`mlx`/`playwright` 是**别的项目**的，不进包） |
| Ollama 二进制 | **32 MB** | ✅ | 静态单文件，**0 个** homebrew 依赖 |
| ffmpeg | 420 KB（二进制）+ 18 个 dylib | ⚠️ | 必须换 static build |
| 图标缓存 | 1 MB | ✅ | 一次抓取永久离线复用 |
| 源码 + 配置 | < 1 MB | ✅ | |
| **合计（不含模型）** | **≈ 150 MB** | | 一个 .dmg 就能装下 |
| qwen3:8b 模型 | **4.9 GB** | ❌ | 首次运行按需下载 |

**为什么"最小依赖只要 25MB"这件事重要**：现有 venv 是 1.4 GB，但那是多个项目混用的。`book2vido` 本身只需要 4 个包——**这正是"打包分发"和"开发环境"的根本区别**。

## 三、三条生死线（打包前必须验，已验）

| 验证项 | 结果 | 影响 |
|---|---|---|
| standalone Python 换目录还能跑吗？ | ✅ 搬到 `/tmp` 后正常 import 标准库、cwd 无关 | 可以内置于 `.app`，用户无需装 Python |
| ffmpeg 能只拷一个文件吗？ | ❌ `otool -L` 显示 **18 个** `/opt/homebrew` 依赖 | **不能**——必须解决（见 §五） |
| ollama 是静态的吗？ | ✅ `otool -L` 显示 **0 个** homebrew 依赖 | 可以只拷 32MB 单文件 |

> 反直觉点：**ffmpeg（420KB）比 ollama（32MB）更难分发**。体积小 ≠ 可移植。

## 四、`.app` 结构

```
dist/Book2Vido.app/
└── Contents/
    ├── Info.plist                # 声明接收 PDF/MD/TXT → 拖拽才响应
    ├── MacOS/
    │   └── Book2Vido             # packaging/launcher.sh
    └── Resources/
        ├── runtime/              # Python（sys.prefix）
        ├── vendor/
        │   ├── ollama            # 32MB 静态二进制
        │   └── ffmpeg            # 可选（static build）
        ├── app/book2vido/        # 源码
        ├── config.yaml           # parents[2]/config.yaml → 落在这里
        └── assets/icons/         # parents[2]/assets/icons → 落在这里
```

**路径为什么这样摆**：`config.yaml` 与 `assets/icons` 都由 `Path(__file__).resolve().parents[2]` 定位。
`__main__.py` 在 `Resources/app/book2vido/` 下 → `parents[2]` = `Resources/` → 两者正好落在 `Resources/` 根。
**挪动 `app/` 的深度会同时打断这两处定位**。

## 五、ffmpeg 问题与解法（当前唯一硬缺口）

homebrew 的 ffmpeg 链接了 18 个动态库（libx264 / libmp3lame / libvpx / openssl…），**拷单个二进制到别的机器必崩**。

三条解法（按推荐度）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **① static build（推荐）** | 下载 arm64 静态版 ffmpeg（无外部 dylib），构建时 `BOOK2VIDO_FFMPEG_SRC=/path/to/ffmpeg bash packaging/build_app.sh` | 单文件约 80 MB，安装包变 230 MB |
| ② 连带打包 dylib | 拷 Cellar 全部依赖 + `install_name_tool` 改 rpath | 52 MB，但要脚本化改 18 个路径，脆 |
| ③ 不内置，要求用户装 | launcher 检测不到就弹窗引导 `brew install ffmpeg` | 违背"一键"，但零成本 |

**当前实现**：构建脚本已支持 `BOOK2VIDO_FFMPEG_SRC` 注入（选①），未注入时走③（弹窗引导）。

## 六、构建与使用

```bash
cd ~/xingtu/book2vido
bash packaging/build_app.sh --check        # 只自检
bash packaging/build_app.sh                # 构建 → dist/Book2Vido.app

# 自检产物
"dist/Book2Vido.app/Contents/MacOS/Book2Vido" --selftest

# 使用
open dist/Book2Vido.app                    # 双击 = 说明 + 打开输出目录
# 或把 PDF 拖到图标上
```

**可用环境变量**（打包到别的机器时用）：

| 变量 | 作用 |
|---|---|
| `BOOK2VIDO_PY_SRC` | 指定 python-build-standalone 目录 |
| `BOOK2VIDO_OLLAMA_SRC` | 指定 ollama 二进制 |
| `BOOK2VIDO_FFMPEG_SRC` | 指定 **static** ffmpeg |
| `BOOK2VIDO_RSVG_SRC` | 指定 rsvg-convert（图标渲染） |
| `BOOK2VIDO_SIGN=1` | 构建后做 ad-hoc 签名 |

**运行期环境变量**：

| 变量 | 作用 |
|---|---|
| `BOOK2VIDO_OUT` | 改输出目录（默认 `~/Movies/Book2Vido`） |
| `BOOK2VIDO_MODEL` | 换模型（默认 `qwen3:8b`） |
| `BOOK2VIDO_FFMPEG` / `_FFPROBE` / `_RSVG` | 强制指定二进制路径 |
| `BOOK2VIDO_VENDOR` | 指定随包二进制目录 |

## 六·补 · `.dmg` 打包（`packaging/build_dmg.sh`）

```bash
bash packaging/build_app.sh          # 先有 dist/Book2Vido.app（dmg 不负责构建）
bash packaging/build_dmg.sh          # → dist/Book2Vido.dmg
```

**职责边界**：`.dmg` **不是"另一种应用"，只是 `.app` 的外层信封**——
把 `Book2Vido.app` + 一个 `/Applications` 软链装进压缩磁盘映像，
用户看到的是"拖进去就装好了"，而不是"一个躺在 dist/ 里的文件夹"。
所以本脚本**不编译任何东西**，也不会修复 `.app` 的任何问题。

三个设计点：
| 点 | 为什么 |
|---|---|
| 用 `ditto` 而不是 `cp -R` | 保留权限位与扩展属性。app 内含可执行文件，权限错一位 → "装上了但点不动" |
| 放 `/Applications` 软链 | 这是"拖进去就装好"的关键，也是用户唯一认得的操作 |
| **打完真挂载校验一次** | 校验卷内 app 存在、软链存在、启动器**仍可执行**。不校验 = 可能发出去一个空盘 |

**实测体积**：`Book2Vido.app` 132 MB → `Book2Vido.dmg` **53 MB**（压缩率 40%，UDZO）。

**实测安装闭环（2026-09-16）**：挂载 dmg → `ditto` 到 `/Applications` → 卷内与安装后自检全绿 →
真实拖 PDF 出片成功（607 KB / 31.4 s / 1080×1920）。
`xattr` 检查**无 quarantine 属性** → 本机双击可直接打开。

## 七、分发形态对比

| 形态 | 优点 | 缺点 | 现阶段建议 |
|---|---|---|---|
| **`.app` 目录 / zip** | 零成本、双击即用 | Gatekeeper 拦未签名应用 | ✅ 已做（`build_app.sh`） |
| **`.dmg`** | **拖进 Applications 的仪式感，"安装"的标准心智** | 未签名仍需绕 Gatekeeper | ✅ **已做**（`build_dmg.sh`，2026-09-16）<br>纯 `hdiutil`，**不依赖 `create-dmg`** |
| `.pkg` | 最像正式产品、可写安装脚本 | 需 **Apple 开发者签名 + 公证**（年费 $99），否则用户要绕 | 对外正式分发时 |
| `brew` formula / tap | 技术人员最爱 | 受众窄 | 开源仓加 tap 即可 |

**Gatekeeper 现实**（必须告知用户）：
未签名 .app 从网上下载后首次打开会提示"无法验证开发者"。绕过方式：
```bash
xattr -dr com.apple.quarantine /Applications/Book2Vido.app
```
**本地构建（不经网盘/浏览器下载）不会带 quarantine 属性，双击可直接开。**

## 八、launcher 的关键设计（踩坑点）

| 设计 | 为什么 |
|---|---|
| `PATH` 收窄为 `runtime/bin:vendor:/usr/bin:/bin` | `.app` 双击时 PATH 极窄；收窄反而让依赖确定 |
| `BOOK2VIDO_VENDOR` 指向 `Resources/vendor` | 让 `binpaths` 优先用随包二进制，而不是用户机器上的 |
| 模型目录**不覆盖** `OLLAMA_MODELS` | 复用已有 `~/.ollama/models`，否则用户白下 4.9 GB |
| ollama 端口先探测再启动 | 系统已有 ollama 在跑时，避免端口冲突 |
| 失败必留痕（通知 + `~/Library/Logs/Book2Vido/`） | 用户看不到终端，静默失败 = 灾难 |
| 0 字节音频当场报错 | 历史 bug：`say` 回退产出空 mp3，崩在很远的 concat 阶段 |

## 九、已知限制

1. **需要联网**：首次下模型 4.9 GB；`edge-tts` 配音也需网（断网可切 `say`）。
2. **ffmpeg 未内置**（当前）：见 §五。
3. **未签名**：对外分发需签名公证，或让用户执行 `xattr`。
4. **仅 Apple Silicon**：runtime / ollama 均为 arm64；Intel Mac 需各自构建。
5. **无 GUI 进度条**：出片当前只在阶段变化/完成/失败时发系统通知。
   **实测时长口径（2026-09-16，整篇 2500 字 / think=true / 12 句）**：
   冷启动 **146.9 s**、热模型 **80.9 s**。
   launcher 通知原写"预计 1–2 分钟"——**低估近一半**，用户会在最后 1 分钟以为程序卡死。已改为「1.5–3 分钟（首次运行更慢）」。
   **教训：面向用户的时长承诺必须来自实测，不能凭感觉写。**
