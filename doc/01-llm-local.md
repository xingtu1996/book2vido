# 01 · 本地 LLM 选型（吐字 + 分镜）

## 角色
把长文 / 书 / 聊天记录压成**口播稿 + 分镜脚本**。这是链路上唯一「不可替代的 AI」环节（抽取、画面、配音都可规则化，只有「压缩成能口播的话」需要语言模型）。

## 选型
| 方案 | 成本 | 质量 | 备注 |
|------|------|------|------|
| **Ollama + Qwen3-8B (Q4, ~5GB)** | 电费 | 中（够用） | **默认首选**。M1 Pro 16GB 可跑，占半内存 |
| Ollama + Qwen3-14B (~9GB) | 电费 | 中上 | 内存吃紧，会卡 |
| FreeToken (UC Berkeley) | 电费 | - | 显存动态调度，备选 |
| 蚂蚁开源轻量 Agent 模型 (1.3B, 8.34GiB) | 电费 | 弱 | 极轻量兜底 |
| DeepLocals (Gemma4-12B 本地知识库) | 电费 | - | 书摘索引 |

## 接入
```bash
brew install ollama
ollama pull qwen3:8b
# OpenAI 兼容 API 在 http://localhost:11434
```
- provider 接口可插拔（`LLMProvider`），无 Ollama 时降级为「规则截取前 N 句」做伪口播，保证端到端先跑通。
- **合规**：本地模型，零公司资源。详见 `CONSTITUTION.md` 铁律一。

## 关键判断
- 本地 8B 写口播稿弱于云端 DeepSeek/Claude，但「压成口播 + 分镜」是中等难度任务，8B 够用。
- boss 已授权「视觉可以少一些」→ 质量容忍度高 → 用「可接受降级」换「零成本 + 零合规风险 + 断网可出片」。
- 趋势：token 越来越便宜 + 本地模型普及 → 这条成本曲线继续下探，时间站在我们这边。

## 性能实测（2026-09-15，M1 Pro 16GB / qwen3:8b Q4_K_M / Ollama 0.33.2）

复现：`python tools/bench_ollama.py`（明细 `/tmp/ollama_bench.json`）

| 指标 | 实测值 | 说明 |
|---|---|---|
| **解码速率** | **14.3 – 17.3 tok/s** | 硬上限，与输入长度无关；≈ 中文 600–700 字/分钟 |
| **预填充** | 177 – **1332 tok/s** | 长文很便宜：2500 字正文喂进去仅约 2s |
| **冷启动** | **4.91s**（加载 5.2GB 到 GPU） | 闲置 5 分钟后卸载，下次重新付这笔钱 |
| **常驻内存** | **5.9GB / 16GB（100% GPU）** | 跑模型时别同时开第二个大模型 |
| **首字延迟（关思考）** | 0.12 – 0.79s | 体验接近在线服务 |
| **首字延迟（开思考）** | 27 – **67s** | 用户要等模型"想完"才看到第一个字 |

### think（思考模式）——必须显式声明
qwen3 在 Ollama 里**默认开启**思考。同一口播稿任务的对照：

| 配置 | 耗时 | 输出 token | 思考字数 | 句子质量 |
|---|---|---|---|---|
| `think=true` | 36.1s | 568 | 738 | 「六层框架散在 6 个工具里」——通顺 |
| 不传（隐式默认＝开） | 38.2s | 583 | 738 | 同上，但**行为不可控** |
| `think=false` | **18.4s** | 152 | 0 | 「用户上手要查六仓」——碎片化、语义可疑 |

结论与取舍：
- **速度**：关思考快约 2 倍，首字延迟从数十秒降到亚秒。
- **质量**：思考确实在提升短句的语义完整度，口播稿场景**不能一刀切关掉**。
- **纪律**：`config.yaml` 里 `llm.think` **必须显式写**，不许依赖模型模板隐式默认——否则换模型/版本会静默改行为，代码里看不出来。口播稿主链路默认 `true`；批量初筛用 `--fast` 临时覆盖为 `false`。

### 容量结论
- 单条 12 句视频：LLM 约 20–40s + TTS/合成约 10s；一条 ~0.4MB。
- 批量 50 篇按 40s/篇 ≈ **33 分钟**，夜间跑完全无压力；磁盘占用约 20–200MB，不是瓶颈。
- 风险点：**16GB 内存下模型常驻 5.9GB**，跑批时避免并行其他重负载；`ollama stop` 或网页台的「卸载模型」可即时释放。

## 成本口径（电费）—— ¥0.0004 是怎么算出来的，以及它**不是**什么

> 本节是口径出处。`demo/README.md` §5 的「成本 ≈ ¥0.0004/条」指向这里。
> **口径 = 电费**，不是省下的钱。

**公式**（代码里三处各写了一遍 —— `pipeline.py` 的 `_stat()`、`pipeline.py` 的批量汇总、
`__main__.py` 的 `_cost_log()`）：

```
电费 = 0.03 kW × 运行秒数 ÷ 3600 × ¥0.6/kWh
```

| 参数 | 取值 | 依据 |
|---|---|---|
| 整机功耗 | **30 W** | ⚠️ **假设值，未实测**（M1 Pro 跑推理时的整机功耗，非"多出来的"功耗） |
| 电价 | **¥0.6 / kWh** | ⚠️ **假设值，未核对实际账单** |
| 时长 | 墙钟差值 | 含抽取 / 渲染 / TTS / 合成的**全部**耗时，不只 LLM 那一环 |

实测样例：`52.3s → ¥0.00026`；`56.6s → ¥0.00028`。

### ⚠️ 三条边界（对外讲这个数字前必读）

1. **它是「花的」，不是「省的」。** 这是本任务消耗的电费，不是省下来的钱。
2. **严格说是「整机电费摊销」，不是「增量电费」。** M1 Pro 待机也在耗电，
   所以这个任务真正的**边际成本 ≈ 0** —— 30W 是整机功耗，不是"因为跑了这件事而多出来的"。
3. **它只覆盖了"没花 API 钱"的一半。** 真正省下的钱在别处：本地推理替代付费 LLM、
   `edge-tts` 免费匿名替代付费 TTS、代码画卡替代文生图。**这部分没有折算成金额** ——
   因为"本来该花多少"没有客观基准（取决于你本来会选哪个付费方案）。
   **若要对外讲"省了多少钱"，必须先把基准说清楚**，否则就是编数（见错题库 L-12 / L-14）。
